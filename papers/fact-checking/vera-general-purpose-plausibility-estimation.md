# VERA: A General-Purpose Plausibility Estimation Model for Commonsense Statements

> VERA：给常识性陈述装一个"可信度打分器"——用约 700 万条从常识问答自动转换的正反陈述训练 T5 打分模型，输入一句话输出 [0,1] 的可信度分数，当验证器用时超过 GPT-3.5/ChatGPT/GPT-4

## 这篇论文到底在解决什么问题？

大模型能写出看起来很聪明的话，但经常犯"低级的常识错误"（比如"鸡比鸟大"）。这类错误光靠生成时约束很难根除，一个自然的补救思路是**事后验证（retrospective verification）**：把模型生成的文本拆成陈述句，逐句问"这句话符合常识吗？"

当时已有的验证手段各有毛病：
- 直接问 GPT 系模型"这句话对吗"——能问，但它们是生成器不是打分器，而且贵；
- 微调一个二分类器——需要人工标注的正反常识陈述，野生文本里根本没有现成标注；
- 专门的 NLI/事实核查模型——覆盖不了开放领域的常识域。

这篇论文（UW + AI2，2023）的答案：**把常识问答和常识知识库自动转成海量"陈述—正误标签"对**（约 700 万条），训练一个通用的陈述可信度打分模型 VERA——输入任何一句陈述，输出 0~1 的打分。

## 他们怎么做的？

**第一步：自动造数据（约 7M 条陈述，零人工标注）**

- **来源一：19 个常识问答数据集（约 200k 组 / 约 400k 句）**。多选题（选正确答案）和是非题（yes/no）天然自带正误标签：正确选项转成正陈述，错误选项转成负陈述；
- **来源二：两个常识知识库 Atomic2020 与 GenericsKB（约 1.6M 组 / 约 6M 句）**。知识库条目本身就是正确陈述，负样本用"条目改写 + 扰动"构造（如换关系、换主体）；
- **LM 增强负样本（LM-augmented falsehoods）**：担心模型只学会识别"人类标注的错"，再让 LM 生成错误答案（生成概率 > 0.15 的候选更可能是 plausible 的错误），混进 9 个 QA 数据集的训练集，提升泛化。

**第二步：两阶段训练（T5 为骨干）**

- 模型输入一句陈述 $x$，取最后一个 token 的隐藏状态过线性层，输出实数分数 $s \in [0,1]$；
- **阶段 1**：先用 KB 构造的语句训练（这些语句相对容易、可能含 false negative，先学粗的）→ **阶段 2**：再用 QA 构造的语句训练（质量更高）；
- **三个训练目标叠加**：
  1. 标准的多选式二分类损失（语句对 "陈述+正确标签" vs "陈述+错误标签"）；
  2. **监督对比损失（supervised contrastive loss）**：把"相似但标签相反"的陈述对在表征空间里拉开——比如"猫比狗大"与"狗比猫大"这种字面几乎一样、语义截然相反的句子，是模型最容易混淆的；
  3. 融入上述 LM 增强的负样本参与训练。

**第三步：校准**

- 打分阈值取 0.5（score > 0.5 判为 plausible）；
- 再做事后校准（post hoc calibration），让输出的分数有概率语义（"0.8 分"大致等于"80% 概率可信"）。

**怎么用（verification format）**：把常识问题改写为陈述句模板（如"Because [原因]..."），用 VERA 对候选陈述打分，取分最高的作为答案——这就把 VERA 变成了可复用的验证器，而不是针对某个数据集重新训。

## 效果怎么样？

- 在 commonsense 验证格式下，VERA **大幅超过能改造成验证器的现有模型，包括 GPT-3.5/ChatGPT/GPT-4**；
- 对比学习目标与 LM 增强负样本都做了消融，各自有效；
- 局限（论文自述）：数据全部来自公开常识资源，对"反直觉但正确"的冷门陈述可能误判；打分是陈述级的，不能区分"句子里半真半假"的细粒度事实（这是 FactScore 走的路）。

## 对谁有用？

- 做"验证器 / 结果型奖励"的人：VERA 展示了一条**纯自动造数据 → 通用打分器**的路线——不依赖人工标注，分数可作为 RL 的稠密/稀疏验证信号；
- 写综述/做组合推理的人：VERA 属于**文本事实核查类奖励**——它核查"陈述—常识事实"的一致性，不含视觉证据，无法为视觉组合绑定提供信号，是"文本偏置"一侧的对照样本。

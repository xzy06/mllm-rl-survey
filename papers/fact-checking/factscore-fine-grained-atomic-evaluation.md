# FActScore: Fine-grained Atomic Evaluation of Factual Precision in Long Form Text Generation

> FActScore：把长篇生成拆成一粒粒"原子事实"，逐个对照可靠知识源算支持率——一段话 66.7% 还是 10.0% 可信，不再是一刀切的"对/错"

## 这篇论文到底在解决什么问题？

长篇文本（人物传记、新闻总结）的事实性怎么评？当时的主流做法是"整篇二分类"：这篇生成对不对？问题在于——

- **一段话往往半真半假**：实测 ChatGPT 生成的人物传记里，约 40% 的句子是"支持与不支持信息混合"的，整句判对错根本说不清哪里错了；
- 人工评估准但贵，不可能规模化。

这篇论文（UW，2023）提出 FActScore（Factual precision in **Atomicity** Score）：**把生成分解成原子事实（atomic fact，只含一条信息的最短陈述），再逐个核对是否被可靠知识源支持，最后算"受支持原子事实占比"**。粒度从"句子"降到"事实"，打分从"0/1"变成"百分比"。

## 他们怎么做的？

**两个关键思想**

1. **原子事实作为单位**：一个句子常含多条信息，例如"Moynahan 在中产阶级家庭长大"+"在洛杉矶长大"是两条独立事实。原子事实 = 只传达一条信息的短陈述（类似摘要的 content unit），比句子更根本；
2. **事实精度是"相对给定知识源"的**：不判"客观上对不对"，而是判"是否被某个用户信任的知识源支持"（沿用事实核查领域惯例）——同一句话，对 Wikipedia 支持、对别的来源可能冲突。

**FActScore 定义**：对生成文本分解出 $N$ 条原子事实，其中 $S$ 条被知识源支持，则

$$\text{FActScore} = \frac{S}{N} \times 100\%$$

**人工评测管线（黄金标准）**：分解（人工）+ 逐条标注是否被给定知识源支持。用于给 InstructGPT、ChatGPT、检索增强的 PerplexityAI 等生成的人物传记打分。

**自动评估器（关键工程）**：把上面管线自动化，让 FActScore 可以应用到任何新模型：

- **分解**：用 ChatGPT 把生成拆成原子事实（输出 JSON 列表）；
- **检索**：用知识源（Wikipedia 文章标题+内容）做检索，为每条原子事实找候选证据；
- **验证**：用 ChatGPT 判定每条原子事实是否被检索到的证据支持，输出 support / not supported / irrelevant；
- 自动评估与人工 FActScore 的**误差率 < 2%**，可以直接替代人工。

**评测发现（用分数倒查模型）**

- ChatGPT 平均每句被拆出约 4.4 条原子事实，其中约 40% 是"支持/不支持混合"的句子——证实整句二分类必然失真；
- 当时的 SOTA 商用模型（含带检索的 PerplexityAI）FActScore 都不高——长文本事实性远未解决。

## 效果怎么样？

- 提供了比整句二分类**更细、更有区分度**的事实性度量：能区分"66.7% 可信"和"10.0% 可信"的两篇生成，而旧方法可能都判"错"或都判"对"；
- 自动评估器误差率 < 2%，成本远低于人工，可迁移到新模型；
- 局限：原子事实分解本身依赖 LLM，分解质量有波动；"是否支持"依赖知识源的选择与检索质量；不覆盖"事实性之外的逻辑/组合一致性"。

## 对谁有用？

- 做评测与数据质量的人：FActScore 是"细粒度分解—验证"范式的代表作，直接可用作长文本事实性指标；
- 写综述/做组合推理的人：FActScore 的**"分解成原子单元→逐条验证→聚合得分"**思想，正是正文 5 节讨论的"把整体奖励拆成可验证子奖励"的文本侧先例——将其迁移到"视觉绑定子奖励"（属性—关系—图像区域）是自然的延伸方向。

# SugarCrepe: Fixing Hackable Benchmarks for Vision-Language Compositionality

> SugarCrepe：修好"能被 hack 的组合评测"——用 LLM 生成语义合理的困难负样本（UW/UIUC/AllenAI，NeurIPS 2023）

## 这篇论文到底在解决什么问题？

组合推理评测基准有一个致命漏洞：**hard negatives 是程序化生成的，往往不合逻辑或不流畅**。比如把"一只猫坐在垫子上"改写成"一只狗坐在垫子上"去配一张没有狗的图——模型根本不用看图，光凭"COCO 里狗和垫子的组合不合理/句式别扭"这类**语言先验**就能分辨正负样本。也就是说：**之前测的可能是"语言 hack 能力"，不是"组合理解能力"。**

为什么以前的方法不行？
- ARO、CREPE 等基准的负样本由规则/模板生成，存在明显的 artifact；
- 模型的"高分"可能来自找 bug 而非真正理解组合关系。

这篇论文想改什么：**让 hard negatives 语义上完全合理、只有组合绑定不同**——模型没有任何语言捷径可走，只能靠真正的视觉-语言组合判断。

## 他们怎么做的？

**核心 idea：用 LLM（GPT-4）生成语义合理的 hard negatives——负样本在语法、语义、流畅度上和正样本一样"像人话"，唯一的差异就是组合绑定（对象/属性/关系）不同。** 技术流派：基准构建（LLM 辅助负样本生成）。

1. **第一步：设计三类扰动形式**（基于 COCO 图文对）：
   - **Replace（替换原子概念）**：Replace-Obj（物体）、Replace-Att（属性）、Replace-Rel（关系）；
   - **Swap（交换两个同类别概念）**：Swap-Obj、Swap-Att——不引入新概念，纯粹考验"谁绑谁"；
   - **Add（添加新概念）**：Add-Obj、Add-Att。
2. **第二步：GPT-4 生成负样本**：对每个正描述，让 GPT-4 按扰动类型生成语义合理、流畅自然的负描述，并用人机校验保证负样本确实与图像不符；
3. **第三步：评测协议**：共 **7,512 个测试样本**，每个样本为"图像 + 正描述 + 硬负描述"的**二选一检索任务**（随机基线 50%）；评测 CLIP、BLIP、ALIGN 等主流模型。

**与同类方法的区别**：ARO/CREPE 用模板程序化生成负样本（可 hack）；SugarCrepe 用 LLM 生成+人工过滤（语义合理）——负样本质量从"机械改写"升级为"自然语言"。

## 效果怎么样？

三个对综述极有价值的关键发现：

1. **模型是"物体中心"的（object-centric）**：物体组合上接近人类水平，但**属性**（Replace-Att 掉约 15%）和**关系**（Replace-Rel 掉约 29%）组合显著落后——组合推理的短板集中在"绑定"而非"识别"；
2. **Swap 形式最难**：所有模型在 Swap 上表现最差（与人类差距达 27%-50%），因为 Swap 不引入新概念，纯粹考验**正确绑定**——这正是组合推理的核心能力；
3. **与 ImageNet zero-shot 准确率强相关（r>0.8）**：组合推理能力与整体视觉理解能力耦合——这暗示"只看整体能力的评测"会掩盖组合短板。

**局限性**：基于 COCO 静态图文对，不覆盖开放场景；二选一检索任务仍可被部分 hack；LLM 生成的负样本质量依赖生成器本身。

## 对谁有用？

- 做 **组合推理评测**的人——"负样本必须语义合理"已成为后续基准的共识；
- 综述定位：**Background 中评测基准的"标杆"**——其 Swap 任务 = 纯绑定测试，可用来判断"奖励信号是否触及组合理解"；其"属性/关系 < 物体"的失败模式是你论文分析组合推理短板的核心证据。
